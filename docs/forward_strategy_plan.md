| 사실 | 근거 | 함의 |
|---|---|---|
| 추세/모멘텀 계열(SMA cross, Dual Momentum, Regime filter) 전부 B&H 대비 초과수익 CI 하한 < 0 | strategy_gate 리포트 | **같은 신호 계열을 더 추가하는 건 무의미** |

| 시드가 소액(수십 달러)이고 실계좌 운용은 월 적립 DCA | run_dca.py 운용 확정 커밋 | **실운용과 같은 현금흐름 구조로 비교해야 의미 있음** |
| 유일하게 근접한 전략은 Regime(QQQ>200d): 수익 포기 대가로 MDD 방어 | strategy_gate 리포트 | 방어는 타이밍(매도)보다 **배분(비중)** 으로 하는 게 비용상 유리 |

따라서 신규 전략은 다음 4개 조건을 전부 만족해야 한다:

1. **신호 계열이 기존과 다를 것** — 추세/모멘텀이 아닌 리스크 기반 또는 역발상(contrarian) 계열
2. **저회전** — 월 1회 리밸런스 이하, 가능하면 매도 자체가 없는 구조
3. **항상 투자 상태 유지** — 현금 도피형 타이밍은 이미 실패 확인됨
4. **기존 심볼 유니버스 재사용** — QQQ/SCHD/GLD/IEF/SPY 등, 신규 데이터 의존성 없음

## 1. 선정 전략

### 전략 A: 역변동성 리스크 패리티 (Inverse-Volatility Risk Parity)

**한 줄 요약**: 각 자산의 최근 실현변동성의 역수에 비례해 비중을 잡는다. 변동성이 커진 자산은 자동으로 줄이고, 안정된 자산은 늘린다. 월 1회만 갱신.

- **유니버스**: `QQQ, SCHD, GLD, IEF` (4자산, 전부 기존 캐시에 있음)
- **신호**: 최근 63거래일(약 3개월) 일간수익률 표준편차 `σ_i` → `w_i = (1/σ_i) / Σ(1/σ_j)`
- **비중 상한**: 자산당 40% cap (IEF 저변동성으로 인한 채권 쏠림 방지), 초과분은 나머지에 비례 배분
- **리밸런스**: 월 1회 + 괴리 5% 임계값 (기존 하네스 규칙 그대로)
- **warmup**: `vol_lookback + 1 = 64` 봉

**이 전략을 택한 이유**:

1. **신호 계열 다변화** — 기존 4개 전략은 전부 "가격 방향"(추세·모멘텀)을 본다. 이건 "가격 방향을 전혀 안 보고" 리스크만 본다. 방향 예측이 9년 백테스트에서 엣지가 없다고 판명된 이상, 예측을 포기하고 리스크 배분만 하는 계열이 논리적 다음 후보다.
2. **항상 투자 + 저회전** — 현금 도피가 없어 Dual Momentum을 죽인 whipsaw(신호 뒤집힘 왕복 비용)가 구조적으로 없다. 변동성은 가격보다 훨씬 천천히 변하므로(변동성 클러스터링) 월간 리밸런스 시 괴리가 작아 실제 매매가 드물다 → 70bps 비용 환경에서 생존 가능.
3. **방어를 매도가 아닌 배분으로** — 위기 때 변동성이 오르면 다음 달 자동으로 주식 비중이 줄어든다. Regime filter가 "전량 탈출"로 하던 방어를 부분 축소로 대체 → 방어 실패 시 기회비용이 절반 이하.
4. **학술·실무적 근거가 가장 탄탄한 무예측 전략** — risk parity / volatility-managed portfolio는 단순 60/40 대비 위험조정수익 개선이 다수 시장·기간에서 재현된 몇 안 되는 결과. 파라미터가 사실상 lookback 하나뿐이라 과최적화 여지도 작다.

**구현 스펙**:

```
파일:   src/toss_trader/strategy/inverse_vol.py
클래스: InverseVolatilityStrategy(symbols, vol_lookback=63, rebalance="month", max_weight=0.40)
```

- `target_weights(ctx)`: 심볼별로 히스토리가 `vol_lookback+1`봉 미만이면 그 심볼 제외. 전 심볼 제외 시 빈 dict(현금).
- `σ_i == 0`(신규상장 정지 등 이상 데이터)이면 해당 심볼 제외.
- cap 적용은 반복 정규화(초과분 재배분 후 재검사, 최대 자산 수만큼 반복)로 처리.
- **월간 게이팅은 인스턴스 상태(`self._key`)가 아니라 순수 함수로 구현** — `period_key(today)`가 바뀐 뒤 첫 호출에서만 재계산하되, 같은 달 안에서는 (today, history)만으로 같은 답이 나오게: "이번 달 첫 거래일 기준 히스토리로 계산"을 명시적으로 코드화. 이유는 §3 하네스 결함 참조.

### 전략 B: 낙폭 가변 DCA (Drawdown-Tilted DCA, 매수 전용)

**한 줄 요약**: 실계좌와 동일한 월 적립 매수를 하되, QQQ가 52주 고점 대비 얼마나 빠졌는지에 따라 그 달 매수분의 배분만 바꾼다. **절대 팔지 않는다.**

- **기본 비중**: 기존 baseline과 동일 `QQQ 60 / SCHD 25 / GLD 15`
- **신호**: `dd = 1 - QQQ종가 / QQQ 252일 최고종가`
- **틸트 규칙** (그 달 신규 적립금의 배분에만 적용):

| QQQ 낙폭 | 해석 | 그 달 매수 배분 |
|---|---|---|
| dd < 10% | 평시 | QQQ 60 / SCHD 25 / GLD 15 (baseline과 동일) |
| 10% ≤ dd < 20% | 조정 | QQQ 75 / SCHD 15 / GLD 10 |
| dd ≥ 20% | 약세장 | QQQ 90 / SCHD 10 / GLD 0 |

- **매도 없음** → 왕복 70bps가 아니라 **편도 ~35bps만** 부담. 기존 전략 대비 비용이 구조적으로 절반.
- **warmup**: 253봉

**이 전략을 택한 이유**:

1. **실운용과 정확히 같은 현금흐름 구조** — 이 계좌의 확정 운용은 월 적립 DCA다(커밋 0c4d78f). 현재 forward 비교의 `dca_etf`는 이름과 달리 일시불 매수라서, 정작 실제로 굴리는 방식의 개선 여부를 아무 전략도 검증하지 않는다. 이 전략이 그 공백을 직접 메운다: "**내가 실제로 하는 DCA를, 규칙 하나 추가로 개선할 수 있는가**"라는 실전 질문에 답한다.
2. **소액·고비용 환경의 이론적 최적 형태** — 매도가 없으면 비용도 절반, 세금 이벤트도 없고, whipsaw도 원천 불가능. 백테스트가 증명한 "비용이 모든 엣지를 먹는다"는 교훈을 가장 극단적으로 수용한 설계.
3. **역발상(contrarian) 계열로 신호 다변화** — 기존 전략들은 떨어지면 판다(추세 순응). 이건 떨어지면 더 산다. 신호 상관이 기존과 음(-)에 가까워 비교 실험의 정보량이 최대화된다.
4. **행동재무적 실익** — "폭락 때 더 사야 하는 걸 알지만 못 산다"를 규칙으로 강제. 파라미터가 임계 2개·틸트 2개뿐이고 방향이 단조(더 빠지면 더 산다)라 과최적화 여지가 작다.

**구현 스펙**:

```
파일:   src/toss_trader/strategy/dd_tilted_dca.py
클래스: DrawdownTiltedDCAStrategy(base_weights, ref_symbol="QQQ", dd_lookback=252,
                                  tiers=((0.10, tilt1), (0.20, tilt2)))
```

- `target_weights(ctx)`는 "그 달 신규 자금의 배분"을 반환. 기존 rebalance 모드로 돌리면 매도가 발생하므로 **하네스에 `mode: "accumulate"` (매수 전용) 추가가 선행 조건** (§3-작업 4).
- 낙폭 산정은 종가 기준(고가 아님) — 캔들 조정 여부가 불명확한 상태에서 고가 사용은 노이즈만 키움.
- ref_symbol 히스토리 부족 시 baseline 비중으로 폴백(전략이 죽지 않게).

## 3. 작업 계획 (순서 고정)

### 작업 0 — 하네스 결함 수정 (P0, 신규 전략보다 먼저)

신규 전략을 지금 하네스에 얹으면 결함까지 상속한다. `scripts/forward_paper_compare.py`의 다음 항목을 먼저 고친다 (상세 근거는 스크립트 평가 참조):

1. **월간 게이팅 파괴 버그**: `_target_weights()`가 매 실행 `spec["factory"]()`로 전략을 새로 만들어 `_key`/`_w` 상태가 초기화 → 백테스트에서 "월 1회"였던 dual_momentum/regime이 forward에선 **매 실행 신호 재계산**이 된다. 수정: 게이팅을 인스턴스 상태에서 분리해 `state`에 `last_signal_period` 저장, 기간이 바뀔 때만 재계산. (백테스트 결과와 비교 가능성을 복원하는 필수 수정)
2. **가짜 Sharpe 제거**: 5분 스냅샷·일간 스냅샷이 섞인 불규칙 시계열에 `√252` 연율화는 무의미. 스냅샷 중 세션당 마지막 것만 골라 일간 수익률로 계산하거나, 표본 < 20이면 `n/a` 표기.
3. **가격 신선도 가드**: `{**캐시종가, **실시간가}` 병합 시 어느 심볼이 stale인지 기록하고, stale 가격으로는 **신규 매매를 금지**(마킹만 허용).
4. **`mode: "accumulate"` 추가**: 매수 전용 + `--monthly-usd` 주기 입금 지원 (전략 B의 선행 조건). 입금 이벤트는 snapshot에 기록해 수익률 계산 시 TWR(기간별 수익률 연결)로 처리 — 입금을 수익으로 오인하지 않게.
5. **상태 파일 원자적 쓰기**: temp 파일 + `os.replace()`.
6. **라벨 정정**: `dca_etf` → `lumpsum_etf` (실제 동작대로).

### 작업 1 — 전략 A 구현: `inverse_vol.py`

- 클래스 + `strategy/__init__.py` export.
- 단위 테스트 (`tests/test_inverse_vol.py`):
  - 변동성 낮은 자산이 더 높은 비중 (합성 데이터로 σ 비율 검증)
  - cap 40% 동작 및 cap 후 합계 = 1.0
  - 히스토리 부족 심볼 제외 / 전 심볼 부족 시 빈 dict
  - σ=0 심볼 제외
  - 같은 달 두 번 호출 시 동일 비중 (게이팅 결정론)

### 작업 2 — 전략 B 구현: `dd_tilted_dca.py`

- 클래스 + export.
- 단위 테스트:
  - dd 5% / 15% / 25% 각 구간에서 정확한 틸트 비중 반환
  - 경계값 (dd = 정확히 10%, 20%)
  - ref_symbol 히스토리 부족 시 baseline 폴백
  - 낙폭 계산이 lookback 창 밖의 고점을 무시하는지

### 작업 3 — 백테스트 게이트 (통과 못 하면 forward 편입 금지)

`scripts/backtest_strategies.py` 프레임에 두 전략 추가, 기존과 동일 조건(2500봉, 실비용 CostModel, 블록 부트스트랩 95% CI):

- **전략 A 합격선**: 대표 B&H 대비 Sharpe 개선 또는 MDD 30% 이상 개선하면서 초과수익 CI가 심하게 음수가 아닐 것. 연간 회전율 < 50% 확인.
- **전략 B 합격선**: 동일 입금 스케줄의 baseline DCA(`run_dca`) 대비 최종 자산 ≥ 및 MDD ≤. 매도 0건 검증.
- 결과는 `reports/strategy_gate_<date>.md`에 기존 형식으로 추가.
- **불합격 시 파라미터 튜닝으로 구제하지 않는다** — 튜닝 통과는 과최적화이며, 그 전략은 기각하고 기록만 남긴다.

### 작업 4 — forward 편입

- `_strategy_specs()`에 두 항목 추가 (A: `mode: "rebalance"`, B: `mode: "accumulate"`).
- `--reset` 없이 기존 state에 신규 전략만 seed로 추가되는지 확인 (`setdefault` 경로가 이미 처리하나, initial_equity 정합성 테스트 필요).
- `--offline-cache` 스모크: 캐시만으로 2회 연속 실행 → 상태 일관성, 리포트에 6개 전략 표기 확인.

### 작업 5 — 문서/운용

- README 또는 docs에 전략별 한 줄 설명 + 이 계획서 링크.
- launchd cron이 forward 스크립트도 주기 실행하도록 할지 결정 (기존 dca_cron과 분리 유지 권장 — 실주문 경로와 절대 안 섞기).

## 4. 성공 판정 기준과 한계 고지

- **Forward paper는 전략 우열을 판정하지 못한다.** 시드 수십 달러 × 수주 관찰로는 통계적 검정력이 0에 가깝다. Forward의 실제 목적은 (1) 비용 모델 현실성 검증, (2) 신호→주문 파이프라인의 운영 버그 검출, (3) 백테스트 대비 회전율 일치 확인이다. 우열 판정은 작업 3의 백테스트 게이트가 담당한다.
- 판정 시점: 편입 후 **최소 60 거래일** 경과 전에는 forward 수익률 순위를 근거로 어떤 운용 변경도 하지 않는다.
- 배당 미반영 상태이므로 SCHD/IEF 비중이 큰 전략은 forward 수치가 구조적으로 저평가됨을 리포트 Notes에 명시한다.
